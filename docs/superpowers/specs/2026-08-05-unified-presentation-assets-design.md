# Unified Presentation Assets Emitter + Author-Owned Templates — Design

**Date:** 2026-08-05
**Status:** Design (awaiting review → implementation plan)

## Goal

Rework the meta-model and library presentation generators so the generated
dictionary carries **only** icon / embedded-asset resources — no
`DataTemplate`s. Entity / class / term visuals become **author-owned**
templates in `presentation/*.mu`, scaffolded once as editable stubs, with a
shared plain-label fallback when a template is absent. The two per-domain
emitters collapse into **one unified asset emitter**.

## Background — current state

Both domains generate `presentation.generated.mu` at publish and on the
*Generate Presentation* command:

- `presentation-generator.ts` → `generatePresentationMu(doc, authorDicts)`
  emits: icon `include`s + one `DataTemplate x:key="mm:<id>" [DataType =
  MetaModelEntity]` per ontology/class entity (icon + baked label box) + a
  `merge` block for author dictionaries.
- `library-presentation-generator.ts` →
  `generateLibraryPresentationMu(doc, authorDicts)` mirrors it, emitting
  `DataTemplate x:key="<classId>" [DataType = LibraryClassData]` per class
  (icon + `$Display`-bound label), reusing the meta-model module's
  `distinctIcons` / `iconKey` / `resolveFacets` helpers.

Wiring (identical in `meta-model-project-factory.ts` and
`library-project-factory.ts`):

- `writePresentation(storage, doc)` → `scanAuthorDicts()` (reads
  `presentation/*.mu`, extracts each `resources <Name>` identifier, sorted)
  → generator → writes `presentation.generated.mu`.
- Called by both `publish()` and `regeneratePresentation()` (the *Generate
  Presentation* command).
- `publishPresentation` / `publishLibraryPresentation` compile the generated
  `.mu` to JS, fail the publish on a missing icon file, and return
  `{ ok, missing, templates, icons }`; the publish message reports the
  `templates`/`icons` counts.

Consumers resolve a **template by key**:

- Toolbox term tiles — `ToolboxService` → `resolveTermTemplate(registry,
  id, concept, label)`: `LibraryRegistry.resolve(classId)` (authored/compiled
  template, else `defaultTemplate`), or a plain `TextBlock` tile.
- Meta-model entity drawer — `ContentTemplate` = the resolved `mm:<id>`
  template; `MetaModelEntity.UITemplate`.
- Canvas nodes — `LibraryRegistry.resolve`.

The generated templates reference icon resources (`@mm_icon_*`) declared in
the same dictionary.

## Non-goals

- No base64 / embedded-document content (wiki pages, thumbnails) now — only a
  commented emit seam for it. (YAGNI.)
- No change to the compiled-presentation load path, the `presentation/`
  merge convention, or `scanAuthorDicts`.
- No change to how consumers resolve a template by key.

## Design

### 1. Unified asset emitter

Replace `generatePresentationMu` and `generateLibraryPresentationMu` with one
shared emitter, `generatePresentationAssets(doc, authorDicts)`, that emits:

- one `include` per distinct icon (`distinctIcons` / `iconKey`) — SVG →
  geometry, raster (`isRasterIcon`) baked to an `ImageBrush` by the
  publisher as today;
- the author `merge` block (`merge <Name>` per `scanAuthorDicts` entry);
- a commented seam (`// --- Embedded content (base64) — reserved. ---`) where
  future embedded assets will emit.

No `DataTemplate`s. The dict is autogenerated and safe to overwrite on every
publish/regenerate. The `resources <Name>` block name is unified across
domains (proposal: `Presentation`); `isRasterIcon` moves into the shared
emitter module. `entityTemplate` / `classTemplate` are deleted from the
emitters (their logic moves to the scaffolder, §2).

Kept and shared: `distinctIcons`, `iconKey`, `resolveFacets`, `humanize`
(icons + scaffolder labels).

### 2. Scaffolder — write-once author stubs

The old `entityTemplate` / `classTemplate` logic is repurposed to **scaffold
an editable author stub** rather than emit into the generated dict. For each
presentable entity/class lacking a stub, write one `presentation/<slug>.mu`
file:

```
resources <SlugName> {
    DataTemplate x:key="mm:<id>" [ DataType = MetaModelEntity ] {
        Border [ Background = @SurfaceContainerHigh, CornerRadius = 6, Padding = (8,6,8,6) ] {
            StackPanel [ Orientation = Horizontal, VerticalAlignment = Center ] {
                Shape [ Geometry = @mm_icon_<slug>, Fill = @OnSurfaceVariant, Width = 16, Height = 16, Margin = (0,0,6,0) ]
                TextBlock [ Text = "<Label>", Style = @BodyMedium, Foreground = @OnSurface ]
            }
        }
    }
}
```

- **Domain difference is isolated here** (the only place it survives):
  meta-model stubs bake the label + `DataType = MetaModelEntity`, key
  `mm:<id>`; library stubs bind `$Display` + `DataType = LibraryClassData`,
  key `<classId>`. The scaffolder takes a small role descriptor
  (`{ dataType, key(id), label(node) | boundLabel }`).
- **Write-once:** never overwrite an existing `presentation/*.mu`. A stub is
  written only when no author file already declares that key. Author edits —
  and deletions — survive regeneration.
- **File naming:** one file per entity, `presentation/<iconKey-style
  slug>.mu`; the `resources` block name is a valid identifier slug of the id.
  (One-file-per-entity chosen for clean per-entity idempotency; the merge
  mechanism already supports many author files.)

### 3. Factory wiring

`writePresentation(storage, doc)` becomes (shared shape across both
factories):

1. `scaffoldStubs(storage, doc, role)` — write missing author stubs
   (write-once, §2).
2. `scanAuthorDicts(storage)` — unchanged (now also finds the scaffolded
   stubs).
3. `generatePresentationAssets(doc, authorDicts)` — icons + merges.
4. write `presentation.generated.mu`.

Both `publish()` and `regeneratePresentation()` keep calling
`writePresentation`, so a freshly published/generated model renders through
its scaffolded (author-owned, editable) templates — no bare label boxes —
while regeneration never clobbers customisation.

**Decision to confirm:** scaffolding runs inside the shared
`writePresentation` (so publish *and* the command both ensure stubs). The
alternative is command-only scaffolding (publish compiles whatever exists).
Shared is proposed for "styled on publish" parity with today.

### 4. Composition & resolution

Unchanged mechanism. The generated assets dict stays the root and `merge`s
`presentation/*.mu` last; author templates resolve their `@mm_icon_*`
references within that merged scope exactly as the baked templates did.

Consumers resolve by key; on a miss → the shared plain-label box that already
exists (`LibraryRegistry.defaultTemplate`, `resolveTermTemplate`'s
`TextBlock` tile). Verify the meta-model drawer / toolbox `mm:<id>` path
degrades to the fallback (or empty) rather than erroring when a key is
unresolved (e.g., author deleted a stub).

### 5. Publish reporting

`publishPresentation` / `publishLibraryPresentation` still compile the dict
(icons) + merged author dicts and fail on a missing icon. The `templates`
count now reflects **author-supplied** templates (scaffolded or authored) in
`presentation/*.mu`, not generated ones; `icons` is unchanged. Update the
publish message text accordingly (e.g., "N author template(s), M icon(s)").

## Affected files

- `meta-model/services/presentation-generator.ts` — becomes the shared asset
  emitter + scaffold-template builders; drop `entityTemplate`.
- `library/services/library-presentation-generator.ts` — removed (folds into
  the shared emitter); `isRasterIcon` moves to the shared module.
- New: `meta-model/services/presentation-scaffold.ts` (or co-located) —
  write-once per-entity stub writer, role-parameterised.
- `meta-model/services/meta-model-project-factory.ts` &
  `library/services/library-project-factory.ts` — `writePresentation` calls
  the scaffolder + shared emitter; pass the domain role.
- `.../presentation-publisher.ts` & `.../library-presentation-publisher.ts` —
  `templates` count semantics + publish message text.
- Tests under each `tests/` subfolder (emitter, scaffolder idempotency,
  factory wiring, fallback resolution).

## Edge cases

- **Regeneration after author edit/delete:** stub write-once → edits kept; a
  deleted stub is *not* re-created only if we key "exists" on the presence of
  the key across `presentation/*.mu` — decision: re-scaffold only when **no**
  author file declares the key, so deleting a stub file *does* bring it back
  on next generate (delete-to-reset). If instead we want permanent deletion,
  track it separately — out of scope; propose delete-to-reset.
- **Id → filename/identifier slug collisions:** two ids slugging to the same
  file. Use the `iconKey`-style slug with a disambiguating suffix if a
  collision is detected.
- **Missing icon at publish** — unchanged: publish blocked with the missing
  path(s).

## Testing

- Emitter: icons-only output, deterministic ordering, author `merge` block,
  no `DataTemplate` lines, embedded seam present.
- Scaffolder: writes a stub per entity; **does not overwrite** an existing
  file; correct per-domain body (baked label vs `$Display`); slug/key.
- Factory: `writePresentation` scaffolds then emits; `publish` /
  `regeneratePresentation` both ensure stubs; publish counts/message.
- Resolution: unresolved key → plain-label fallback, no error.

## Out of scope / future

- Base64 embedded content (wiki pages, images-as-data) — emitter seam only.
- Per-concept default template tiers (already a TODO in `LibraryRegistry`).
