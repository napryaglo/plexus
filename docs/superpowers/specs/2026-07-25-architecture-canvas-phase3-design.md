# Architecture Canvas (Phase 3) — Design

**Status:** Designed for implementation (one combined spec). Final phase of the library arc (Phase 1 publish bundle ✓, Phase 2 LibraryRegistry ✓).
**Date:** 2026-07-25

## Problem

An architecture project binds a meta-model + libraries and authors instance `.todl`. Phase 3 makes that visual and interactive: a **concept-aware canvas** where a user drags a library **class** from a palette onto a diagram to create a typed **instance**, rendered through the class's library template; moving, editing, and connecting nodes round-trips to `.todl`. The **TODL instance graph is the source of truth**; the canvas is a live view; the `.todl` is generated by a new **graph→`.todl` emitter** and validated by the existing pipeline.

## Current-state grounding (from feasibility investigations)

**Mural canvas — no framework changes required.**
- `Diagram extends Selector`; `GetContainerForItemOverride(item)` returns a `Figure`/`Group` directly or wraps an item in a `Figure` and binds `DataContext`. Subclassable from Plexus.
- `Figure extends ContentControl` — has `Content` / `ContentTemplate` / `Template` DPs (plus `Left`/`Top`/`Geometry`/`Fill`/`Text`). Overriding the `Figure` template to add a `ContentPresenter` lets a node render an arbitrary `DataTemplate`. Content-driven sizing is **not** supported (explicit `W`/`H`) — v1 uses a fixed node size.
- `DiagramDocument.CreateNode(kind,x,y)`; `Nodes` + `Connectors` (endpoints carry `.Node`); `Save()/Load()` over a **closed** `SerializedNode` schema (no per-node data bag).
- Drop: `attachCanvasDropBehavior`, `TOOLBOX_NODE_KIND_FORMAT`, `Diagram.AddItemDroppedListener`, `DropReceiver` DP. A custom `plexus/class-ref` drop format coexists with the toolbox format.
- Exports (from `@pragmatic-lab/mural/framework`): `Diagram`, `DiagramDocument`, `Figure`, `Group`, `ToolboxShape`, `SHAPE_CATALOG`, `attachCanvasDropBehavior`, `TOOLBOX_NODE_KIND_FORMAT`.

**TODL instance graph — mutation + reactivity exist; source emission does not.**
- `Repository`: `builder()`, `resolve(id)`, `instancesOf(concept)`, `isClass(id)`, `classOf(leaf)`, `effectiveFields(leaf)`, `changed: Signal<GraphChangeArgs>`; schema types `ConceptSchema`/`FieldSchema`/`RelationshipSchema`.
- `Builder`: `assertInstance(typeOf, id, asClass?)`, `setField(id, name, value)`, `addRelationship(from, name, to)`, `addInstanceOf(leaf, cls)`, `commit()`.
- Observable: `Repository.changed` (`GraphChangeArgs { kind, node, property, target }`), `ReactiveNode` (`propertyChanged`/`collectionChanged`).
- `toJSON`/`fromJSON` ↔ `TodlDocument { nodes: JsonNode[], edges: JsonEdge[] }`; `parse(source,uri)`, `load`, `checkAgainst(bases, sources)`.
- **No graph→source emitter exists** — Phase 3 builds one (Unit B). Instance syntax (verified in fixtures): `<concept> <id> [instanceof <class>] { field = value; ref = &target; list = [&a, &b]; }`.

## Architecture

```
.archdiagram (layout: instanceId → x/y) ┐                    ┌─▶ emitter ─▶ .todl (instances) ─▶ TodlValidationService ─▶ Problems
.todl (instances) ──────────────────────┴─▶ Repository ◀── Builder ◀── canvas edits (drop / move / set / connect)
   bases via resolveBases (meta-model+libs) ─▶  │
                                                └─▶ node per own instance ── LibraryRegistry.resolve(classId).Apply(InstanceNodeVM)
```

The `Repository` is seeded with the project's **bases** (so class/relationship schemas are known) and then the project's **own instances**. The canvas renders one node per own instance; connectors mirror relationship edges. Every edit mutates the graph via `Builder`; the emitter regenerates the `.todl`; positions persist in the `.archdiagram`.

## Units

### A · Instance model service (`architecture-instance-model.ts`, headless)

Owns one `Repository` per open architecture-diagram document.
- `load(bases: TodlDocument[], instanceSource: string): ArchInstanceModel` — build a `Repository` from `fromJSON(mergedBases)` (or `checkAgainst`) and parse/load the instance `.todl` into it, recording which node ids are **own** (from the instance source) vs **base** (classes/concepts). Exposes `ownInstances(): NodeId[]`.
- Mutation ops (each a `Builder` batch + `commit`): `createInstance(classId): NodeId` (fresh id; `assertInstance(concept, id)` + `addInstanceOf(id, classId)`), `setField(id, name, value)`, `addRelationship(from, member, to)`, `removeRelationship(from, member, to)`, `remove(id)`.
- Schema query for connectors: `relationshipCandidates(fromId, toId): RelationshipSchema[]` — relationship members of `fromId`'s class whose target concept `toId` satisfies.
- `changed: Signal<GraphChangeArgs>` re-exposed for the canvas to react to.

### B · graph→`.todl` emitter (`todl-emitter.ts`, headless) — the new component

`emitInstances(model: ArchInstanceModel, namespace: string): string`. Walks the **own** instances → emits one `namespace <ns> { … }` block, each instance:
`<concept> <localId> instanceof <classLocalId> { <field> = <value>; <relMember> = &<targetLocalId>; <manyRel> = [&a, &b]; }`
- `concept` = the meta concept the class realises (`resolve(classOf(i)).typeOf`); `classLocalId` = the class's local name.
- Scalar fields from the instance's own attrs (not class-fixed inherited values); strings quoted, numbers/bools bare.
- Relationship edges → `&ref` assignments, single or `[…]` list per the member's cardinality.
- **Correctness gate:** round-trip test — a sample instance `.todl` → `load` → `emitInstances` → `parse`/`load` again yields an equal graph (compared via `toJSON`).

### C · InstanceNodeVM (`instance-node-vm.ts`)

A mural `Model` wrapping one graph instance — the DataContext a class template binds to.
- DPs: `Display` (label ?? localId ?? id), plus a generic field accessor bound reactively. Field edits call `model.setField`; `Repository.changed` for the node updates the VM (two-way).
- `ClassId` + `Concept` exposed so the canvas resolves the template.

### D · Concept-aware canvas (`arch-diagram.ts` + Figure content template)

- `ArchDiagram extends Diagram` (Plexus): `GetContainerForItemOverride` builds a `Figure` whose `Content` = the node's `InstanceNodeVM` and whose `ContentTemplate` = `LibraryRegistry.resolve(vm.ClassId, vm.Concept)` (default box when untemplated); fixed default size; `Left`/`Top` from layout.
- A Plexus `Figure` template (markup) adds a `ContentPresenter [ Content = $Content, ContentTemplate = $ContentTemplate ]` over the shape slot.
- Nodes bound to `model.ownInstances()` (materialised as `InstanceNodeVM`s); reacts to `changed` (instance added/removed → node added/removed).

### E · Palette + drag-create + connectors

- **Palette:** the project's bound libraries (manifest `libraries[]`) → their classes via `LibraryRegistry`; each tile draggable, emitting `plexus/class-ref` = `{ classId }`.
- **Drop:** `ArchDiagram` listens for `plexus/class-ref` → `model.createInstance(classId)` at the drop point → node appears (reactive) → layout records x/y → emit + save.
- **Connect:** on a connector drawn A→B, `relationshipCandidates(A,B)` → **one** ⇒ `addRelationship` silently; **several** ⇒ a small chooser popover to pick the member; **none** ⇒ reject with a status/Problems message. Deleting a connector → `removeRelationship`. Connectors are derived from relationship edges (not free-drawn geometry).

### F · Document type + persistence + wiring

- New **`architecture-diagram`** document type (extension `.archdiagram`) contributed by the architecture module. The file holds **layout** (`{ nodes: { instanceId: {x,y} }, version }`) + the instance-namespace name; the sibling `<name>.todl` holds the emitted instances (human-readable, validated).
- **Open:** read `.archdiagram` → resolve bases (`resolveBases` from the project manifest) → load `<name>.todl` into the model → materialise nodes at saved positions.
- **Save:** `emitInstances` → write `<name>.todl`; write `.archdiagram` layout. The written `.todl` is picked up by `TodlValidationService` (it already validates project `.todl` against bases) → Problems dock.
- Wiring: `ArchDiagramDocumentFactory` (open/save/new) registered on the architecture module; a Plexus resources file for the `Figure` content template + palette + `DataTemplate[architecture-diagram document]`; app merges + `compile:mu` + any icon.

## v1 scope

- **In:** instance nodes (scalar fields + `instanceof`), **connectors** (relationship edges), move/edit/delete, drag-create from the bound-library palette, `.todl` emit + validate, layout persistence, reopen.
- **Out (later):** containment/nesting of instances, content-driven node sizing (fixed size v1), multiple diagrams per model / multiple views, live text-edit of the emitted `.todl` merged back without regeneration (the canvas owns formatting), auto-thumbnail generation.

## Error handling

- Unresolved bases (unpublished meta-model/library) → the existing `resolveBases` problems surface via the validator (project-level Problems entry); the palette shows only classes whose library resolved.
- A class with no template → the default box (Phase 2 resolver).
- A connector with no compatible relationship → rejected with a transient message; nothing mutates.
- Emit/parse failure → surfaced as a document-level Problems entry; save is blocked rather than writing a corrupt `.todl`.

## Testing

- **Emitter (B):** round-trip — sample instance `.todl` → load → emit → re-parse equals (via `toJSON`); covers scalar fields, single + list relationships, `instanceof`.
- **Instance model (A):** `createInstance` yields an own instance of the class; `setField`/`addRelationship`/`remove` mutate the graph; `relationshipCandidates` returns the schema-valid members.
- **InstanceNodeVM (C):** field edit writes through to the graph; a graph change updates the VM.
- **Canvas/palette/persistence (D–F):** service-level tests (node set built from the model; drop creates an instance; connect resolves a candidate; save emits + writes layout; reopen restores positions) + a live `npm run dev` smoke.

## Open contracts to verify during implementation

1. **Mural connector API** — how `Connectors` are created/observed (`Diagram` connector-drawn event/endpoint shape) and whether connector creation is user-drivable without geometry, to map to relationship edges.
2. **`Figure` content template** — the exact DP names for binding `Content`/`ContentTemplate` in the overridden template, and that a `ContentPresenter` inside a `Figure` template renders at the figure's box.
3. **Building a seeded `Repository`** — the exact call to construct a `Repository` from base `TodlDocument`s plus loaded instance source (whether via `fromJSON` + a load-into-existing path, or `checkAgainst` then wrapping) such that class schemas are queryable and own vs base ids are distinguishable.
4. **`.archdiagram` document plumbing** — reuse of the generic `DiagramDocument` for layout vs a bespoke document model; how the architecture-project document factory routes `.archdiagram` to the canvas editor.
